# Rancana 1.0.34 — Optimasi `__hitungPersentasev2`

Route: `POST /pic/simpan-persentase-v2` → `PersentaseController::__hitungPersentasev2`
Masalah: proses lambat / error ±3 menit ketika data besar (puluhan/ribuan kantor).

## Hasil Diagnosis (lokal)

| Bagian | Waktu |
| --- | --- |
| `PicController::__dataYangDitampilkan` kantor terbesar (2.610 baris, 87 NIP) | ~0,45–2,0 s |
| `AsnDariApi::get()` + `usort` + field display | tidak terpakai untuk hitung % |
| `__jumlahkanBeberapaKode` dipanggil per baris hari (2.234×) | ~0,03 s (boros, bukan biang) |

Penyebab struktural (menjadi berat saat data besar):

1. `app/Http/Controllers/PersentaseController.php:183` memakai `PicController::__dataYangDitampilkan()` yang dibuat untuk tampilan: load seluruh tabel `asn_dari_apis` (tidak dipakai untuk hitung %), membangun field display, `usort`, dan agregasi dijalankan di dalam loop harian (30× per NIP).
2. `->get()` mengambil semua kolom seluruh baris bulan tersebut → ratusan ribu model di-hydrate untuk kantor besar.
3. `PersentaseController.php:209-213` → 1 `UPDATE` per NIP di dalam transaksi (ribuan statement).
4. Tabel `data_absens` hanya punya `unique(nip, date)` — tidak ada index `(unor_simpegnas_id, date)` → full scan setiap request.
5. Halaman GET `persentasev2()` (`PersentaseController.php:101-108`) memakai `whereYear()` + `whereDay()` pada kolom `date` berjenis `varchar` → full scan dan mengambil semua kolom; berjalan setiap redirect sesudah POST (kandidat kuat "3 menit").
6. `ListKantor::...->get()[0]` (`PersentaseController.php:166`) → error undefined key bila kantor tidak cocok.

## Langkah Pekerjaan

### 1. Migration index `data_absens`

- `index(['unor_simpegnas_id', 'date'])`
- `index('date')` (untuk halaman listing)
- Catatan: build index pada tabel produksi besar membutuhkan jendela maintenance.

### 2. Tulis ulang `PersentaseController::__hitungPersentasev2` (`:150`)

- Validasi tetap; `first()` lalu redirect `->with('error', ...)` bila kantor tidak ditemukan (view sudah merender `session('error')`).
- Query hanya kolom `nip, nama, date, hari_libur, status, status_change, status_script` + filter `unor_simpegnas_id` dan `date LIKE 'Y-m%'`, diproses via `chunkById(2000)` → akumulasi jumlah kode per NIP (memori datar untuk ribuan ASN).
- Per NIP: panggil `__jumlahkanBeberapaKode` sekali (bukan per hari), rumus bobot + `round()` disalin verbatim dari kode sebelumnya (hasil identik).
- Mengganti N+1 `update()` dengan satu `DataAbsen::upsert($rows, ['nip', 'date'], ['persentase'])` di-chunk 500 (pola sudah dipakai di `DataAbsenController.php:214`), hanya untuk NIP yang punya baris tanggal-01 (sama dengan perilaku `update()` lama yang no-op).
- Perhitungan di luar transaksi; transaksi hanya membungkus batch upsert.
- Membuang `AsnDariApi::get()`, `usort`, dan field display dari jalur ini.

### 3. `PicController::__jumlahkanBeberapaKode` (`:317`)

- `private` → `public` (tanpa perubahan logika → sumber aturan tunggal, tanpa duplikasi).
- Opsional: memindahkan pemanggilannya keluar loop harian di `__dataYangDitampilkan` (halaman rekap ikut lebih cepat, hasil sama).

### 4. GET `persentasev2()` (`:101`)

- `select('unor_simpegnas', 'date', 'persentase')`.
- Mengganti `whereYear`/`whereDay` dengan `whereIn('date', ['Y-01-01' … 'Y-12-01'])` → memakai index, tanpa fungsi pada kolom.
- Grouping di view tetap.

### 5. Verifikasi

- Test Pest `HitungPersentaseV2Test` + factory `ListKantor`/`DataAbsen`:
  - persentase tertulis di baris `Y-m-01`,
  - baris hari lain tidak berubah,
  - kantor tidak dikenal → redirect + flash error.
- Cek paritas: hasil % lama per NIP disimpan sebelum refactor (baca saja), dibandingkan sesudah refactor → nilainya identik.
- Benchmark before/after kantor `DIKES - PKM KUMBE` (2.610 baris).
- `vendor/bin/pint --dirty --format agent` dan `php artisan test --compact`.

## Tidak Disentuh

- Route, view, struktur kolom database.
- `__hitungPersentase` (v1) — punya pola masalah sama, menjadi tindak lanjut.
- Langkah Telescope / `TELESCOPE_ENABLED` — dilewati sesuai permintaan.
